Laravel Bearer Token API Tests

This page calls the Laravel API (run1-5-docker.sh) from the browser with fetch(). Each button runs one test. Read the code at the bottom of this file to see how a Bearer token is sent.

Configuration

Start the containers first: bash run1-5-docker.sh (Docker, port 8000)

Current token: (none)

Part 1: Connection and Login

Test 1.1: Server Connection

GET /api/students is public and needs no token.

Test 1.2: Wrong Password

POST /api/login with a wrong password must return 401 and no token.

Test 1.3: Login

POST /api/login returns a Bearer token. The page keeps it in a JavaScript variable.

Part 2: Bearer Token Checks on GET /api/me

Test 2.1: Missing Token

No Authorization header: expect 401.

Test 2.2: Invalid Token

Authorization: Bearer invalid-token: expect 401.

Test 2.3: Valid Token

Send the token from the login: expect 200 and the logged-in user.

Part 3: Students (reads are public, writes need a token)

Test 3.1: Get All Students

GET /api/students: public.

Test 3.2: Get One Student

GET /api/students/{id}: public. An unknown id returns 404.

Test 3.3: Create Student

POST /api/students: 401 without a token, 201 with a token.

Test 3.4: Update Student

PUT /api/students/{id} with a token. Only the changed field is sent.

Test 3.5: Delete Student

DELETE /api/students/{id} with a token. A later GET must return 404.

Test 3.6: Validation Errors

Bad input returns 422 with an errors object.

Part 4: Logout

Test 4.1: Logout Revokes the Token

POST /api/logout deletes the token. The same token must then return 401.
